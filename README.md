## 개인정보를 어떻게 나눠 두었는지

이 저장소는 **공개**입니다. GitHub Pages 무료 플랜이 공개 저장소를 요구하기 때문입니다.
그래서 민감한 정도에 따라 자료를 세 곳에 나눠 두었습니다.

| 자료 | 어디에 | 누가 볼 수 있나 |
|---|---|---|
| 학번별 시간표 | `ttdata.js` (공개 저장소) | 누구나. 이름이 없어 누구 것인지는 알 수 없습니다 |
| 학생 이름 명단 | Firestore `students` | **선생님만** |
| 상담·행동특성 누가기록 | Firestore `records` | **선생님만.** 학생 본인도 못 봅니다 |
| 면담 신청자 이름·사유 | Firestore `bookingDetails` | **선생님만** |

**학생 이름은 코드에 넣지 않았습니다.** 미성년자 21명의 이름과 시간표가 함께 공개
저장소에 올라가면 검색에도 걸리기 때문입니다. 이름은 선생님이 로그인한 뒤
**학생 기록 → 명단 등록**에서 한 번 붙여 넣으면 Firestore에 저장됩니다.

**학번 로그인은 비밀번호가 아닙니다.** 학번은 서로 다 아는 값이라 누구나 남의 학번을
넣어 볼 수 있습니다. 그래서 학번으로 볼 수 있는 것은 **시간표뿐**이고, 누가기록이나
남의 면담 내용은 학번을 넣어도 절대 보이지 않습니다.

### 규칙 갱신하는 법

Firebase 콘솔 → **Firestore Database → 규칙** 탭에 `firestore.rules` 내용을 통째로
붙여넣고, `TEACHER_EMAIL` 자리에 선생님 계정 이메일을 적은 뒤 **게시**를 누릅니다.

```
&& request.auth.token.email in ['선생님이메일@example.com'];
```

**이걸 하기 전에는 누가기록을 쓰지 마세요.** 새 컬렉션(`students`, `records`,
`resources`)에 대한 규칙이 없으면 기본값에 따라 막히거나 열립니다.

## 고치고 싶을 때

```bash
git clone https://github.com/JunRepos/schoollife.git
```

고쳐서 push 하면 1~2분 뒤 사이트에 반영됩니다.

- **일과 시간·면담 시간대** → `index.html` 의 `SLOTS`, `COUNSEL` 배열
- **시간표** → `ttdata.js`. 학기가 바뀌면 새 엑셀로 다시 만들어야 합니다
- **자료실 분류** → `index.html` 의 `CATS`
- **누가기록 구분(상담/행동특성/칭찬/기타)** → `index.html` 의 `KINDS`

## 알아 두실 점

**예약 취소** — 지금은 예약을 만든 기기에서만 취소 버튼이 보이지만, 규칙상 취소 요청
자체는 막지 않습니다. 선생님만 취소할 수 있게 하려면 `firestore.rules` 의
`match /bookings/{id}` 에서 `allow delete: if true;` 를 `allow delete: if isTeacher();` 로
바꾸세요.

**내린 전달사항** — ‘내리기’ 한 공지는 학생 화면에서 사라지지만 데이터베이스에는 남아
있어 마음먹으면 읽을 수 있습니다. 남기면 안 되는 내용은 ‘삭제’를 쓰세요.

**누가기록은 학교 공식 기록이 아닙니다** — 나이스(NEIS)에 옮겨 적기 전의 메모장으로
쓰는 것을 전제로 만들었습니다. 학교 규정상 학생 자료를 외부 서비스에 두어도 되는지는
한 번 확인해 보시는 편이 좋습니다.

**무료 한도** — Firestore 무료 한도는 하루 읽기 5만 건입니다. 한 학급 규모면 충분합니다.
